# Adaptive context

The AtomNano session owns the conversation, task board and portable memory. Role briefs follow the configured project workflow. Provider threads and provider-side prompt caches are separate. Changing a model, provider or account does not require a new AtomNano session.

- Only the primary conversation is history: the user's prompts, the primary model's replies and its own tool calls, including each Agent / Task call with its result. Entries produced inside a sub-agent (its tool calls, text and thinking) never travel into a fresh thread, a summary, a digest or a handoff; the transfer note says how many were left out. They stay in the record and are retrievable with `atomnano context read`.
- A compatible native thread resumes with only the new prompt and any history it missed. Its acceptance cursor advances only after the provider accepts the input.
- A fresh thread receives exact history when it fits the model allowance. Large tool-only payloads may use small labelled excerpts. Oversized history, overflow recovery and explicit Synthesize use an adaptive working handoff.
- The working handoff budgets 12–32 KiB according to recent requests, outcomes and open tasks. Budgets count UTF-8 bytes, including the synthesis wrapper; they do not cap native model context. It carries saved memory, selected newer requests/constraints, recent replies, tool results/failures, board state and exact source references.
- Cached memory is portable and reused immediately, even when the archive has grown. Newer evidence is selected locally. Foreground preparation never runs a catch-up chain over the archive.
- Cold preparation asks for at most one summary, from at most 32 KiB of selected evidence, with a 20-second request deadline. Empty, failed or timed-out summaries fall back to labelled source excerpts. A queue wait also has a deadline; the whole preparation is limited to 30 seconds. Stop aborts instead of falling back and sending an abandoned request.
- A background digest can update memory from its previous summary plus a bounded selection of new evidence. Foreground work can cancel that background preparation. This is an extra model call when enabled, not a free provider cache read.

Selected memory is explicitly labelled as incomplete. It is not proof that every source entry was read. The full transcript and recorded tool outcomes stay intact. Use `atomnano context search` and `atomnano context read` to retrieve details from archived or live entries, with stable message IDs and byte pagination; see [CLI](cli.md#read-saved-context).

Synthesize creates a new AtomNano session by explicit request in the same project, with its active workflow, retained model/settings and a copied task board. Ordinary provider/model/account switches continue the existing session. Claude's local transcript remains resumable across credential changes. Codex starts a new native thread when its auth context changes and transfers context from the app record, including through the SDK fallback. Old account capacity measurements do not restrict the new account. Provider prompt-cache hits cannot be assumed to transfer between accounts or providers.

# Model capacity

Provider discovery supplies numeric capacities for existing and new models. A legacy `oneM: false` cannot force a supported one-million-token model down to 200K. Custom endpoints can declare `ctx` or `contextWindow`. Real provider reports and learned rejection limits govern the usable window, scoped to their model and account.

Codex exposes both `context_window` (default) and `max_context_window` (supported maximum). AtomNano uses the larger valid value and explicitly sets `model_context_window` and a proportional compaction limit for app-server and SDK fallback requests. Provider-reported usable capacity may reserve output space; that measurement is not fed back as the next configuration value, which would progressively shrink the window. Cached input is part of total input and is counted once.

No sub-agent outlives the run that started it. A run that finishes, is stopped or fails ends its agents; a run that pauses on a network, login or rate-limit error (kept for retry, never finalised) ends them too, because its CLI process is gone; records of runs that no longer exist are ended when the Agents panel lists them, when Stop is pressed with nothing running, or when a new run launches its first agent. A session read from disk (after a restart or a crash) holds no live work: agents and tool cards it persisted as running are ended on load, and a clean quit persists them as ended before the app exits. An agent that ends without a report of its own keeps its last activity on the record ("… Last activity: Tracing recovery stop in generateEntry.ts"), shown in the panel, the card popover and the finished strip. Every ended agent frees its CPU-governor slot, so freed slots are reused.

The cap you set is the limit. The composer's "Agents · 3" is the number running right now; the cap ("up to N at once", 1–20) sits in the Agents popover and is handed to the CLI as its hard limit. Claude decides when delegating speeds the work up. The CPU gate ("Yield to heavy processes") is opt-in and off by default: on, new agents wait for a free slot while a build saturates the machine and the agent process runs at lower priority. The governor reads the cap from the running turn, never from a different settings file, and every surface (button, strip, popover, drawer, slots line) counts agents from the same registry. The cores-per-agent knob left the UI. A strip chip or a popover row opens the Agents drawer on that agent; drawer cards are left-aligned with the head on one line. Reviewers moved from the composer row to the chat header's ⋮ menu; the 1M chip is an indicator, not a checkbox.

The exec transport commits a new native binding only after turn acceptance, not merely thread creation. Accepted tool outcomes advance the cursor even when a turn pauses for a network, rate-limit or authentication failure. Retry keeps its original prompt identity and paused status. A stopped or superseded run cannot advance a newer run's cursor or replace its binding.

Verified 2026-09-17: [OpenAI GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol) specifies 1,050,000 context tokens; [Codex configuration](https://learn.chatgpt.com/docs/config-file/config-sample) documents native window overrides. The installed account catalog can specify a smaller maximum and takes precedence over a published API fallback. [Anthropic's model table](https://platform.claude.com/docs/en/about-claude/models/overview) lists 1M for Fable 5.1, Opus 5 and Sonnet 5, and 200K for Haiku 4.5. Unknown models are not automatically labelled as 1M.

# Validation

`npm test` includes byte-bound Unicode handoffs, 20 MB archived history, a 600 MiB logical planning fixture, zero-call cached reuse across providers, native resume, account-change transfers through both Codex transports, exec turn acceptance and failed-attempt continuation, stopped/superseded Claude events, cancellation, timeout fallback, capacity discovery and exact history retrieval. `smoke-tests/test-session-preparation.js` covers Synthesize, repeated clicks, Stop then immediate Send, late results and rendering in an isolated Electron profile. These use fake providers and no paid model probes.
